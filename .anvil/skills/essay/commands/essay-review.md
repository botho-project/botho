# essay-review — Reviewer

**Role**: reviewer (single content critic + deterministic gate runner).
**Reads**: latest `<thread>.{N}/<thread>.md` (+ `provenance.md` when the claim ledger has ≥1 row — issue #1198), project `BRIEF.md` (+ resolved `voice:` docs), `<thread>/refs/` + shared `research/`, `rubric.md`, any consumer `.anvil/skills/essay/rubric.overrides.md` (additive only), prior `<thread>.{M}.review/` siblings (M < N) to track whether prior issues were addressed.
**Writes**: `<thread>.{N}.review/` with `verdict.md`, `scoring.md`, `comments.md`, `_summary.md`, `_gate.json`, `_meta.json`, `_progress.json` — plus the gate sidecars `<thread>.{N}.numeric/` and `<thread>.{N}.hyperlinks/` written by the gate CLIs themselves.

The review sibling is **read-only once written**. Revisions consume it; they never modify it.

## Outputs

```
<thread>.{N}.review/
  verdict.md       Advance / block + total /44 + critical-flag paragraphs + top revision priorities
  scoring.md       Per-dimension table: # | Dimension | Weight | Score | Justification
  comments.md      Line-level comments (severity blocker/major/minor/nit + scope preserve/expand/reduce),
                   optionally carrying a `Downstream risk:` line per finding (issue #1197 — step 6c)
  _summary.md      Machine-readable blocks: rubric block, voice_grounding (when author tier active), subject_voice_grounding (when subject tier active — #598), provenance_back_check (when corpus tier active — #611), claim_ledger (when the ledger has ≥1 row — #1198), gates echo, scope_distribution
  _gate.json       Deterministic pre-flight record (see step 3)
  _meta.json       { critic, role, started, finished, model, schema_version, scorecard_kind: "human-verdict",
                     rubric_id: "anvil-essay-v1", rubric_total: 44, advance_threshold: 35 }
  _progress.json   Phase state for the reviewer
```

**Atomicity** (issues #350, #376): written atomically via `anvil/lib/sidecar.py` — files staged under `.<thread>.{N}.review.tmp/`, atomically renamed on clean completion; stale staging from a prior interrupt of THIS critic removed by `cleanup_one_staging(<thread>.{N}.review)` at entry, and an orphaned move-aside backup from an interrupted replace (issue #881) recovered by `recover_interrupted_replace(<thread>.{N}.review)` alongside it; the gate CLIs manage their own `.numeric/` / `.hyperlinks/` sidecars.

## Procedure

1. **Discover state, sweep, open sidecar**: find the highest `N` with `<thread>.{N}/<thread>.md` (slug-echo per #295); run `cleanup_one_staging(<thread>.{N}.review)`, **then `recover_interrupted_replace(<thread>.{N}.review)`**.

   **Both sweeps are mandatory, and both run before the idempotency check** (issue #881). They cover the two distinct crash shapes this command can leave behind, and neither can see the other's:

   - `cleanup_one_staging` sweeps a leftover `.<thread>.{N}.review.tmp/` — the `.tmp` crash path (issue #376).
   - `recover_interrupted_replace` recovers a leftover `.<thread>.{N}.review.bak/` — the `.bak` crash path introduced by the replace surface below. This command is **markdown-driven, with no Python driver**: the window between `stage_replace` and `commit_replace` spans many discrete tool calls (seven file writes, then the commit), and this session can die inside it — context exhaustion, process kill, orchestrator timeout are all first-class expected failure modes here. When it does, no `except` handler survives to call `abort_replace`, `<thread>.{N}.review/` is *absent* (it was renamed aside), and the only copy of the legacy content sits in the hidden `.bak` sibling. Without this sweep the next run takes the "dir does not exist" branch, lands a fresh review over the gap, and **silently strands the legacy `review.md` forever** — invisible to `anvil:rubric-rebackport` and `project-migrate --adopt-review`, and never swept (every staging sweep in this framework matches the `.tmp` shape only). `recover_interrupted_replace` restores the dir byte-identical, after which the recognizability check below sees the legacy content again and re-enters the replace path from a clean state. It is an idempotent no-op (one `stat`) when no backup exists, so run it unconditionally.

   The primitives back this up rather than trusting the doc: `stage_enter` and `commit_staged` — the split CLI-shim surface a driverless session like this one actually drives (tier 1 below) — both **refuse** with `FileExistsError` while an orphaned `.bak` is on disk, so skipping this sweep fails loudly instead of losing content silently. `stage_replace`'s absent-`final_dir` error likewise points at `recover_interrupted_replace` (not `stage_enter`) when a backup holds the only copy.

   **Idempotency check is content-aware, not bare directory-existence** (issue #881). Determine whether `<thread>.{N}.review/` already carries a **recognizable** anvil review by checking `anvil/lib/critics.py::_has_recognizable_review()` — `True` for a canonical `_review.json`, or the complete `verdict.md` + `scoring.md` + `comments.md` triple this very command writes. Three cases:

   - **Dir does not exist** → open `staged_sidecar(final_dir=<thread>.{N}.review, required_files=["verdict.md", "scoring.md", "comments.md", "_summary.md", "_gate.json", "_meta.json", "_progress.json"])` and write everything inside the staging dir, exactly as before.
   - **Dir exists AND is recognizable** → exit early (idempotent) — byte-identical to pre-#881 behavior for the common case of a real prior essay-review.
   - **Dir exists but is NOT recognizable** — occupied only by foreign, pre-anvil content (the canonical case: `anvil:project-migrate --apply` moved a legacy single-file `review.md` into this exact path, and nothing anvil-shaped has written there since). This is the **migrated-corpus case** (issue #881). Do NOT exit early — that would silently treat unreviewed foreign content as "already reviewed." Do NOT call `staged_sidecar` / `stage_enter` directly either — both correctly refuse via `FileExistsError` on an existing `final_dir`, because they cannot themselves distinguish foreign occupancy from a real review (that distinction is this step's job, not theirs — the #350 immutability guard they enforce stays exactly as strict). Instead use the parallel `anvil/lib/sidecar.py::stage_replace` / `commit_replace` / `abort_replace` surface, which generalizes the move-aside/stage/swap recipe `project-migrate`'s `--adopt-review` already uses for the adjacent problem (`anvil/skills/project-migrate/lib/adopt_review.py::_convert_one`):
     - `stage_replace(<thread>.{N}.review)` re-verifies recognizability itself (refusing with `FileExistsError` if the dir turns out to already carry a real review — belt-and-suspenders on the #350 guard) and, once confirmed foreign-only, moves the dir aside to a `.bak` sibling and returns a fresh staging dir already seeded with everything that was there (e.g. `review.md`, copied byte-identical).
     - Write this pass's required files into that same staging dir (alongside the preserved foreign file(s), exactly as with `staged_sidecar`).
     - `commit_replace(<thread>.{N}.review, required_files=["review.md", "verdict.md", "scoring.md", "comments.md", "_summary.md", "_gate.json", "_meta.json", "_progress.json"])` (the essay manifest **plus every preserved foreign filename** — `review.md` here — so the atomic swap only lands once BOTH the new review AND the old content are confirmed present) verifies the manifest and atomically swaps the merged staging dir into place, then drops the backup.
     - On any failure while writing between `stage_replace` and `commit_replace` that this session can still catch, call `abort_replace(<thread>.{N}.review)` to restore the original foreign content untouched and discard the partial staging dir. A failure this session *cannot* catch — the session simply ends mid-window — is covered instead by the mandatory `recover_interrupted_replace` entry sweep at the top of this step, which the **next** run executes; the two together close both halves of the recovery story (same-session and cross-session).
     - The legacy file lands **under its original name, inside the same sidecar dir** it always occupied — `anvil:rubric-rebackport` and `project-migrate --adopt-review` continue to discover it at `<thread>.{N}.review/review.md` afterward (both still walk on the exact filename `review.md`; nothing about its path or bytes changed). The merged dir now passes `_has_recognizable_review()` (the essay triple is present), so a rerun idempotently skips it like any other completed review.

   Initialize `_progress.json` and `_meta.json` with `scorecard_kind: "human-verdict"`, **`rubric_id: "anvil-essay-v1"`, `rubric_total: 44`, `advance_threshold: 35`** (per-review version stamping, issue #346). Load `<thread>.{N-1}.review/_meta.json` when present and cache `prior_rubric_id` for the `_summary.md` rubric block (omit on first iteration).

   **Non-Python-driver ordering (fail-open, manual fallback)** — issue #645: `staged_sidecar` is a Python context manager. A manual/agent session with **no orchestrating Python driver** cannot hold its `with` block open across the file writes below (it writes files with its own editing tool between discrete steps), so it MUST use the equivalent CLI shim rather than writing straight into the final `<thread>.{N}.review/` dir (which silently reopens the #350 partial-write defect this primitive exists to close). Two tiers, in preference order:

   1. **Primary — `python -m anvil.lib.sidecar` CLI shim** (the common case). In an installed consumer repo (anvil vendored under `.anvil/`, not on `sys.path`), prefix every invocation below with `uv run --project .anvil` (the `.anvil/pyproject.toml` + `uv sync --project .anvil` shipped by the installer since #230 make the module resolvable from the consumer root — the same shape the other `anvil.lib.*` critics already use); in the anvil source repo the bare `python -m anvil.lib.sidecar` form works as-is. This wraps the *exact same* `staged_sidecar` code, so the manifest check + single atomic `Path.rename` are enforced by code, not agent discipline:
      - `uv run --project .anvil python -m anvil.lib.sidecar stage <thread>.{N}.review` → prints the staging path (`.<thread>.{N}.review.tmp/`). (Refuses with a nonzero exit if `<thread>.{N}.review/` already exists — matching `staged_sidecar`'s `FileExistsError` refuse-to-overwrite guard.)
      - Write **all** required files (`verdict.md`, `scoring.md`, `comments.md`, `_summary.md`, `_gate.json`, `_meta.json`, `_progress.json`) into that printed staging path — never into the final `<thread>.{N}.review/` name.
      - `uv run --project .anvil python -m anvil.lib.sidecar commit <thread>.{N}.review --required verdict.md,scoring.md,comments.md,_summary.md,_gate.json,_meta.json,_progress.json` → verifies the manifest, then atomically renames staging → final. **Nonzero exit (1) leaves the staging dir in place with no partial final dir** if any required file is missing — the `SidecarIncompleteError` analog; fix the gap and re-`commit`.
      - Both entry sweeps of step 1 have exact CLI analogs, and both are mandatory: `uv run --project .anvil python -m anvil.lib.sidecar cleanup <thread>.{N}.review` (the parallel-safe per-critic `.tmp` sweep, issue #376) **and** `uv run --project .anvil python -m anvil.lib.sidecar recover-replace <thread>.{N}.review` (the `.bak` cross-session recovery sweep, issue #881 — exit 0 always, prints what it did; an idempotent no-op when there is no backup). A CLI-driven session is the *most* exposed to the cross-session crash, since every file write is a separate tool call.
      - The **migrated-corpus case** (step 1's third bullet, issue #881) has an exact CLI analog too: `uv run --project .anvil python -m anvil.lib.sidecar replace <thread>.{N}.review` (prints the staging path, seeded with the preserved foreign content; refuses with a nonzero exit if the dir is absent or already recognizable) → write the required files into the printed path → `uv run --project .anvil python -m anvil.lib.sidecar commit-replace <thread>.{N}.review --required review.md,verdict.md,scoring.md,comments.md,_summary.md,_gate.json,_meta.json,_progress.json` → verifies the manifest and atomically swaps staging into place, dropping the backup. `uv run --project .anvil python -m anvil.lib.sidecar abort-replace <thread>.{N}.review` restores the original content untouched if a write between `replace` and `commit-replace` fails *and this session is still alive to run it*; if the session dies instead, the next run's mandatory `recover-replace` entry sweep does the same job.
   2. **Last resort — manual `mv`-based staging** when even `python`/`uv` is unavailable. Reproduce the staging contract by hand: (a) at entry, sweep any leftover `rm -rf .<thread>.{N}.review.tmp/` (the `cleanup_one_staging` analog); (b) `mkdir .<thread>.{N}.review.tmp/` and write **every** required file into it — writing `_progress.json` **last**, so a mid-write interrupt is caught by the missing-manifest check rather than producing a final-named partial; (c) confirm the staging dir holds the full required set — use a count check (`[ "$(ls -1 .<staging-dir> | wc -l)" -eq <N> ]`) or an `ls`-based presence check rather than per-file `[ -f ]`, which can false-negative under a restricted-`stat` sandbox — **then** `mv .<thread>.{N}.review.tmp <thread>.{N}.review` as the **last** step (POSIX `mv` on a same-filesystem dir-to-dir rename is atomic, matching `Path.rename`). Do NOT create `<thread>.{N}.review/` before all files are staged. **Record the fallback durably** so a reader can tell atomicity was reproduced by hand rather than tool-verified: stamp `_meta.json` with `"atomicity_fallback": "manual-mv"` (e.g. `sidecar: staged_sidecar CLI unavailable (uv/python not on PATH); atomicity reproduced via manual mv this pass`). Absent this note the manual staging is indistinguishable from an unsafe direct write.

   The two tiers land a byte-identical on-disk result to the `staged_sidecar` context-manager path; they exist only to give a Python-less session a code-enforced (tier 1) or contract-faithful (tier 2) route to the same atomicity guarantee. When an orchestrating Python driver IS present, use `staged_sidecar` directly as documented above — the CLI shim is not needed. (If your agent harness pattern-matches and rejects filenames like `verdict.md` / `scoring.md` / `comments.md` on a `Write`, a Bash-heredoc write into the staging dir is an accepted fallback — see `anvil/lib/snippets/critics.md` §"Orchestrator output-file guard collisions".)

2. **Read inputs**: the body, the matching BRIEF `documents:` entry (`target_length` when declared; default envelope 500–1500 words; measure it with `python -m anvil.lib.word_count <body>` — the one canonical method, #1349, never raw `wc -w`), `rubric.md`, consumer rubric overrides, `<thread>.{N}/_progress.json` (the drafter's self-check + `metadata.voice_exemplars`), and any previous review for this slug.
3. **Run the deterministic pre-flight gates (BEFORE any judgment)** and record every outcome in `_gate.json`:
   - **3a. Numeric consistency — BLOCKING** (issue #462's hook, built for this skill): invoke `uv run --project .anvil python -m anvil.lib.numeric_consistency <thread>.{N}/ --write-review --blocking`. The CLI writes the `<thread>.{N}.numeric/_review.json` sidecar via its own `staged_sidecar`; under `--blocking` it emits one `CriticalFlag` per finding-code cluster, which forces `Verdict.BLOCK` through `critics.compute_verdict`. Mirror each cluster as a **Numeric-consistency failure** critical-flag paragraph in `verdict.md` (rubric flag 7) quoting the claim, the named values, and the actual arithmetic. Per-claim suppression (`<!-- anvil-lint-disable: numeric_consistency -->`) is honored by the CLI (suppressed hits surface as info, never gate). An essay with zero numbers passes vacuously.
   - **3b. Hyperlink resolution — BLOCKING for broken/unresolvable links**: invoke `python -m anvil.lib.hyperlink_resolver <thread>.{N}/ --write-review` (the module promoted from the memo skill-local lib under this skill — #335/#460; add `--check-external` only when the operator asks for an online pass). The CLI writes `<thread>.{N}.hyperlinks/_review.json`. Unresolved cross-thread refs raise `critical_broken_cross_thread_anchor` (BLOCK via the aggregator); broken markdown-internal and wiki links arrive as `major` findings — **escalate them to a blocking verdict** when still unresolved at verdict time (step 8): a published essay with a dead internal link fails the publish-handoff guarantee. An essay with zero links passes vacuously (the coverage *judgment* at step 5d still runs).
   - **3c. Rhetoric lint — ADVISORY** (issue #463): run `anvil/lib/rhetoric_lint.py::lint_rhetoric` over the body. **Consumer rule resolution first** (issues #468/#479 — the `voice.rhetoric_rules` BRIEF sub-key, the memo-render step 4g contract ported to this direct call): call `anvil.lib.project_brief.resolve_rhetoric_rules(<project_dir>)` with the same `<project_dir>` (the BRIEF-bearing project root) that step 4 passes to `resolve_voice_docs` — derive it once and share it, don't re-derive. Then:
     - **`None` returned** (no BRIEF / malformed BRIEF / no `voice:` block / no `rhetoric_rules` sub-key / whitespace-only value) → **omit the `extra_rules_path=` kwarg** entirely; the framework default rule set (`anvil/lib/rhetoric_lint.py::DEFAULT_RHETORIC_RULES`) applies — defaults-only behavior is byte-identical whether or not a `voice:` block is present.
     - **Resolved entry with `missing == False`** → pass `extra_rules_path=entry.paths[0]` (project-root hit wins over consumer-root fallback; absolute declared paths bypass the walk — the `resolve_voice_docs` precedent).
     - **Resolved entry with `missing == True`** (declared-but-missing file) → **still pass the path**: `extra_rules_path=<project_dir>/<entry.declared>` (the declared path verbatim when it is absolute). Do NOT silently omit the kwarg — `lint_rhetoric`'s loader graceful-degrades to a defaults-only run **plus one warning finding naming the error**, so the broken declaration surfaces in the lint result and the existing `_gate.json` `rhetoric.warnings` count ("a defect to surface, not an opt-out"; zero new error machinery).

     Note the kwarg asymmetry with memo: memo-render forwards through `render_gate.gate(kind="memo", rhetoric_rules_path=...)`; this command calls `lint_rhetoric` **directly**, so the kwarg is `extra_rules_path=`. Consumer rules tune *which* findings fire, never their severity ceiling, and `rhetoric_rules` does not activate the voice-grounding judgment tier at step 4 (`resolve_voice_docs` never returns it; a `rhetoric_rules`-only `voice:` block keeps `VoiceDocs.is_empty` True). Findings are warning-ceiling **by contract — do NOT escalate severities, do NOT fold them into a critical flag, do NOT force `advance: false` from lint output alone**. They feed two judgment surfaces: deterministic evidence for the dim 9 justification (step 6) and assist material for the generic-AI-cadence flag (step 7), where the judgment call stays the reviewer's (irreducible false positives: quoted material, deliberate style).
   - **Write `_gate.json`** (inside the staging dir): `{ "numeric": {"ran": true, "blocking": true, "pass": <bool>, "findings": <count>, "critical_clusters": <count>}, "hyperlinks": {"ran": true, "pass": <bool>, "broken_internal": <count>, "broken_cross_thread": <count>, "external_probed": <bool>}, "rhetoric": {"ran": true, "advisory": true, "warnings": <count>, "infos": <count>} }`.
4. **Load voice grounding (conditional — issue #461)**: invoke `anvil/lib/project_brief/voice.py::resolve_voice_docs(<project_dir>, exclude_self_slug=<thread>)` per `anvil/lib/snippets/voice_grounding.md`. Passing `exclude_self_slug=<thread>` is **mandatory for this command** (issue #890) — it is the fix for the circular-calibration defect where reviewing a *revision of an already-published* thread resolves that thread's own prior published form inside its own `voice.corpus` glob, calibrating dim 2 against the artifact under review.
   - **When active**: read the resolved docs (values → style_guide → vocabulary → corpus exemplars); read `metadata.voice_exemplars` from the version's `_progress.json` to verify the drafter's grounding happened. Declared-but-missing files → a **`major` finding** in `comments.md` directing the operator to create or fix each file (tier stays active; record the missing paths for `_summary.md.voice_grounding.missing`). Cache the resolved list for steps 6 (dim 2), 7 (flags 1–2), and 9 (`_summary.md`).
   - **Self-published exclusion (issue #890)**: the resolved `corpus` entry's `excluded` / `exclusion_reasons` fields name any paths `resolve_voice_docs` dropped as `<thread>`'s own published form — one of two unioned sources: **automatic inference** (a matched filename stem, after stripping one optional leading `YYYY-MM-DD-` date prefix, exactly equals `<thread>` case-insensitively) or a **declared `voice_corpus_exclude`** on `<thread>`'s `documents:` entry (the escape hatch for a publish-path shape the automatic rule cannot infer — e.g. a title-cased or nested filename). When `excluded` is non-empty, cache it for step 9's `_summary.md.voice_grounding.corpus_excluded` block — do NOT silently drop the information; the whole point is that the calibration base stays auditable.
     - **Thin-corpus guard**: after exclusion, if the corpus tier is active (not `missing`) and fewer than **2** exemplar paths remain, do NOT calibrate dim 2 as if the base were unaffected. Append `"; corpus thin after self-exclusion — <N> exemplar(s) remain, calibration reliability reduced"` to the dim 2 triggered suffix (step 6) and cache `corpus_thin: true` (+ `remaining_exemplars: <N>`) for `_summary.md`. This applies whether `<N>` is 1 (the exclusion left a single exemplar — still score dim 2, but say so) or 0 (nothing left to calibrate against — dim 2 scores uncalibrated for this pass, same posture as the inactive-tier case below, but the `voice_grounding` block still emits `ran: true` since the tier *is* declared and active, just currently starved).
   - **When inactive (no `voice:` block, `voice: {}`, or no BRIEF)**: record a **`major` finding recommending the operator declare the `voice:` block** — voice is the point of this artifact class; an absent contract is a defect to surface, not a crash and not silence (SKILL.md §Voice grounding — the deliberate divergence from memo's byte-identical-silence posture). Dim 2 still scores, uncalibrated; no `_summary.md.voice_grounding` block is emitted.
4b. **Load subject voice grounding (conditional — issue #598)**: invoke `anvil/lib/project_brief/voice.py::resolve_subject_voice_docs(<project_dir>)` (the same `<project_dir>` as step 4; the **subject tier activates independently** of the author tier — a `subjects`-only `voice:` block returns `[]` from `resolve_voice_docs` but entries here) per `anvil/lib/snippets/voice_grounding.md` §"Subject voice tier".
   - **When active** (≥1 declared subject): read each subject's resolved `corpus` (spoken transcripts) + `voice_doc` (when present); read `metadata.subject_voice_exemplars` from the version's `_progress.json` to verify the drafter's per-speaker grounding happened. Declared-but-missing corpora/voice_docs → a **`major` finding** in `comments.md` per subject directing the operator to create or fix each file (tier stays active; record the missing paths for `_summary.md.subject_voice_grounding[].missing`). Cache the resolved subject list for step 6 (dim 2 per-subject pass), step 7 (Misattribution flag 8), and step 9 (`_summary.md`).
   - **When inactive** (no `subjects` list, empty list, or no BRIEF): the subject tier does not exist for this project — no finding, no `subject_voice_grounding` block (byte-identical to pre-#598). This is the customer-context activation convention, NOT the author-tier's declare-the-block recommendation: subjects are opt-in (most essays render no third-party dialogue), so their absence is silence, not a defect.
4c. **Provenance back-check (conditional — issue #611)**: invoke `anvil/lib/project_brief/voice.py::resolve_corpus_dirs(<project_dir>)` (the same `<project_dir>` as steps 4 and 4b; the **corpus tier activates independently** of the voice tiers) per `anvil/lib/snippets/provenance.md` §Section 1.
   - **When active** (≥1 resolved dir): read `metadata.corpus_dirs_resolved` from the version's `_progress.json` to verify the drafter ran. **Anchor-drift pre-check (issue #868, cheap and deterministic — run over the WHOLE table, not just the sample)**: `python -m anvil.lib.provenance_anchor check <thread>.{N}/provenance.md <corpus_root> [...]` (prefix `uv run --project .anvil` in an installed consumer repo) BEFORE the manual spot-sample below. Since essay ships no audit command, this is the only exhaustive check its provenance tier gets — but it is exhaustive only for the *drift* axis (mechanical), not the *content* axis (still judgment, still sampled). A `DRIFTED` row is NOT flagged `major`/`blocker` here — record a distinct `comments.md` note ("Line range hint stale — anchor drift, run `essay-revise` to repoint mechanically") and read the passage at its resolved location, not the stale hint, for the spot-sample judgment below if that row happens to be sampled. **Spot-sample rows from `<thread>.{N}/provenance.md`** — see step 4d immediately below for WHICH rows: the claim-ledger priority list, not an arbitrary sample. Emit findings as **`kind: judgment`** with `evidence_span` pointing at the map row (`provenance.md:L<N>`), **quoting both the claim and the cited passage** (vague back-check feedback without a quoted passage is itself a defective finding, the §Section 3 evidence discipline). A row whose cited file is **not resolvable** under any corpus root → **`major`** finding. A row whose cited passage **does not support the claim as written** → **`blocker`** finding. A **missing `provenance.md`** when the tier is active → **`major`** finding directing the operator to re-draft with provenance tracking (a broken contract, not a crash). The back-check is a **sampling** check by design for content — the exhaustive five-way audit pass is out of essay's surface (essay ships no audit command; that is paper's follow-on).
   - **When inactive** (no `corpus:` key, `corpus: null`, or `corpus: []`): byte-identical to pre-#611 — no block, no findings, no `provenance_back_check` section in `_summary.md`, UNLESS step 4d's claim ledger is active on `derived` rows alone (see below).
   - **Declared-but-missing dirs**: the tier still activates; `resolve_corpus_dirs` returns `missing: true` entries (never raises) — surface the broken declaration as a **`major`** finding.
4d. **Claim ledger — prioritized batching, not re-derivation (conditional — issue #1198)**: this step activates whenever `<thread>.{N}/provenance.md` exists with ≥1 row — a SUPERSET of step 4c's corpus-tier activation (a `derived`-only ledger with `corpus:` inactive still runs this step; see `anvil/skills/essay/lib/claim_ledger.py` for the full row-shape/design-decision rationale). This is Failure 3's fix (#888): the ledger tells this pass exactly what needs checking, so effort stops going to re-verifying unchanged claims while never-checked ones sit untouched.
   - **Compute the priority batch**: `python -m anvil.skills.essay.lib.claim_ledger check <thread>.{N}/provenance.md <corpus_root> [...]` (prefix `uv run --project .anvil` in an installed consumer repo; pass the resolved corpus roots from step 4c when the corpus tier is active, else no roots — `derived` rows are never drift-checked mechanically). The report's `priority_lines` is the union of `NEVER_VERIFIED` rows (never checked by any pass — the exact #888 failure: an inherited claim surviving unverified for rounds) and `NEEDS_REVERIFY` rows (a `corpus` row whose #868 anchor drifted or vanished since it was last verified). Rows already `VERIFIED_CURRENT` are NOT re-derived from scratch this pass — that is the waste #888 names ("effort went to re-verifying what was already verified").
   - **Check every priority row in THIS SAME pass, not one per revision cycle**: `Kind: corpus` rows follow step 4c's back-check (open the cited passage, quote claim + passage, classify per §Section 5). `Kind: derived` rows are checked by judgment against their free-text `Source file` reference (open the named `refs/`/`research/` file or re-derive the fact from the named linked repo/reference) — same finding severities as 4c (`major` for an unresolvable reference, `blocker` for a reference that does not support the claim as written), same quoted-evidence discipline. **Fold every priority-row finding into THIS `comments.md`** — the direct fix for the trickling shape #888 documents (`.5` a restructure plus four corrections, `.6` three more hunks, when one consolidated pass could have caught everything visible at `.2`).

Record the line numbers of every priority row that raised NO finding this pass in `_summary.md.claim_ledger.checked_clean_lines` (see step 9) — this is the list `essay-revise` stamps into `<thread>.{N+1}/provenance.md` via `mark-verified` (see `essay-revise.md` step 5b). A priority row that instead raised a finding is deliberately left off this list, so it still shows up as a priority row next pass until the finding is actually addressed.
   - **Record `metadata.claim_ledger_summary`** (`anvil.skills.essay.lib.claim_ledger::summarize`) in `_summary.md` (see step 9) — never gates the verdict on its own; an unverified/stale row that could not be cleared this pass surfaces as the ordinary `major`/`blocker` finding above, which DOES feed the verdict through the existing machinery.
   - **When inactive** (no `provenance.md`, or an empty ledger with zero rows): byte-identical to no ledger at all — no block, no findings, no `claim_ledger_summary` in `_summary.md`.
5. **LLM coherence passes (before scoring)** — the three sister moves ported from the consumer's blog-review, covering what craft scoring misses:
   - **5a. Dinner-party register lens** (step-2 port): does this read like *sharing at the dinner party*, or like *winning an argument*? Quote 1–2 lines that demonstrate the answer; apply the lens across every scored dimension; feeds dim 6 directly.
   - **5b. Example-coherence pass** (step-2.5 port — **BLOCKING via LLM critical flag**): restate the essay's central abstract claim in one sentence; restate the central worked example in one sentence; ask whether the example *physically needs* what the claim says is the gate. Also catch: metaphors fighting the underlying physics; cost claims conflating dollars/joules/latency/bandwidth/area; "X requires Y" where Y isn't binding; closing images trading plausibility for romance. On failure, raise the **Example-coherence failure** critical flag (rubric flag 6): quote the framing sentence AND the example, and state what the example actually needs (the toaster failure is the canonical instance). No detector exists by design (#462 gate 1) — this prose check is the gate.
   - **5c. Full claim-vs-claim numeric pass** (step-2.6 port): the step-3a detector is the deterministic extraction assist UNDER this pass, not a replacement for it. List every number; for each spread/gap/percentage/multiplier claim, do the arithmetic; flag claims referencing a broader population the essay never bridges to; catch the shapes the detector cannot prove (the same quantity stated twice disagreeing across sections, spelled-out numbers). Real failures raise the **Numeric-consistency failure** critical flag (rubric flag 7) with the arithmetic shown.
   - **5d. Link-coverage judgment** (step-2.7 port — `major`, never critical): for every specific named entity (paper, benchmark, leaderboard, project, organization, product), apply the dinner-party-in-reverse test — if a friend asked "where do I find that?", would the author hand over a URL? Unlinked references-worth-linking become `major` `comments.md` entries feeding dim 7. Skip household-name brands as background, common infrastructure, public figures (their *works* may still warrant links), and cultural-shorthand sampling. Missing links are polish, not blockers — this half never raises a critical flag (the deterministic broken-link half at 3b is the blocking surface).
   - **5e. Thesis-unity check** (issue #1148 — `major`, never critical): restate the essay's single argument in one sentence — the same "restate … in one sentence" framing 5b uses for the central claim and example. Then test each `##`-level section against that one sentence: would deleting this section weaken the argument? A section whose deletion would NOT weaken the argument — however well-crafted, well-transitioned, or factually sound — becomes a `major` `comments.md` entry (`scope: reduce`) feeding dim 7, naming the section and stating plainly why the essay's argument survives its removal. This check runs REGARDLESS of whether the section also appears on the "What's working" list (see "What essay-review does NOT do" below) — craft quality and thesis relevance are independent axes, and a section can be simultaneously a voice signature worth protecting and a tangent worth cutting. Like 5d, this is polish/scope territory, never a critical flag: the operator may deliberately want the tangent and can keep it knowingly. **Zero or one `##`-level sections** (short essays are often unsectioned prose) → nothing to test a section against — the check passes vacuously, matching the zero-numbers / zero-links convention at 3a/3b; do NOT force a vacuous finding.

Use inline `"..."` spans, NOT blockquotes (justifications live in single table cells). A dim scored at **full weight** MAY substitute the by-absence marker `no instance of <X> found` — absence of defects has no quotable span; below ceiling the quote requirement stands. The quote must be byte-verbatim from the body — a paraphrase presented in quote marks is fabricated evidence, the defect class the step 6b self-check exists to catch. **Elision with `...` / `…` is permitted** (issue #478): a quote may skip intervening text with an ellipsis, provided each elided fragment is itself verbatim, ≥ `MIN_QUOTE_CHARS` normalized chars, in document order, and drawn from one nearby passage (within the verifier's `ELISION_WINDOW_CHARS` proximity window) — do NOT stitch fragments from distant sections into one quote. Em/en dashes may be typed as `--` / `---` (the verifier folds dash variants symmetrically). (Voice deductions under the dim 2 sub-step quote BOTH the offending essay passage per this rule AND the corpus exemplar per `voice_grounding.md` — the two contracts are complementary; see the step 6b note on exemplar quotes.)
   - **Dim 2 (Voice fidelity — owned)**: when the voice tier is active, score against the resolved docs per `anvil/lib/snippets/voice_grounding.md` §Reviewer contract. **Every voice deduction MUST quote a corpus exemplar** showing what the target sounds like (count the quotes for `_summary.md.voice_grounding.exemplars_quoted`); apply the **convergence-with-Claude adversarial check** (*would I, the AI, also write this sentence?* — if yes, scrutinize harder, never defend); check voice signatures and vocabulary tells in prose (deterministic counting belongs to the 3c lint). When the tier is inactive, score dim 2 uncalibrated and note `"no voice contract declared — dim 2 scored without corpus calibration (see the major finding)"`.
     - **Per-subject voice-fidelity sub-pass (issue #598 — when the subject tier is active from step 4b)**: within this same dim 2 score, run a **per-subject pass** over each speaker's rendered dialogue against that speaker's resolved transcript corpus (+ `voice_doc` when present) per `voice_grounding.md` §"Subject voice tier". **Every subject-voice deduction MUST quote the transcript** showing the speaker's actual cadence **alongside the drifting reconstructed line** (quote the transcript, quote the drifting line) — vague feedback like `"doesn't sound like her"` without a transcript quote is itself a defective finding. Apply the **generalized convergence-with-Claude check**: *would I, the AI, also write this line for this speaker?* — if yes, scrutinize harder; a polished balanced sentence where the corpus shows clipped declaratives is the canonical failure mode. Per subject, count the transcript passages quoted (→ `subject_voice_grounding[].exemplars_quoted`) and the lines deducted (→ `subject_voice_grounding[].lines_flagged`). The per-subject deductions fold into the single dim 2 score — this is NOT a new rubric dimension and the rubric total stays /44. Append `"; subject voice tier active — <N> subject(s) scored against transcript corpora, subject-voice deductions must quote transcripts"` to the dim 2 suffix.
   - **Dim 9 (Rhetorical economy — load-bearing)**: cite specific anti-pattern instances (throat-clearing, trailing recaps, hedge cushions, non-load-bearing paragraphs, length past the envelope) AND cite relevant 3c lint findings as advisory evidence (never as forced deductions). Apply the plain-language-first distinction between padding and patient teaching per `anvil/lib/snippets/plain_language.md` and `anvil/lib/snippets/rubric.md` §"Dim 9 — teaching-oriented length is not padding" (issue #1042) — a passage that explains a term in ordinary language before naming it is not a deduction target. **Echo rule**: every cited dim 9 instance ALSO appears as a `scope: reduce` entry in `comments.md` so the reviser sees the trim directive in the comment stream it consumes.
   - Remaining dims per their rubric.md rows; dim 6 consumes 5a; dim 7 consumes 5d plus 5e plus the argument-chain judgment.
6b. **Validate quoted evidence (deterministic, write-time self-check)** — issue #464 / #475:
   - After the `scoring.md` write lands inside the staging dir, invoke `uv run --project .anvil python -m anvil.lib.evidence_check <thread>.{N}/ --scoring <staging dir>/scoring.md` (or call `anvil.lib.evidence_check::check_version_dir(<thread>.{N}/, scoring=<staging dir>/scoring.md)` directly). The verifier parses the scoring table via `anvil/lib/critics.py::parse_memo_scoring_table`, extracts the quoted spans from each justification, and checks each one against `<thread>.md` (curly→straight quote folding, dash-variant folding `—`/`–`/`---`/`--`, whitespace collapse, markdown-emphasis stripping; case-sensitive substring match, with `...`/`…`-elided spans matched fragment-by-fragment in document order within the `ELISION_WINDOW_CHARS` proximity window — issue #478). Classification per justification: ≥1 span matching the body → pass; score at full weight + `no instance of <X> found` marker → pass (ceiling-by-absence); spans present but none matching → **major `fabricated_evidence` finding**; no spans at all → minor `missing_evidence` advisory. Anchors are NOT validated (judgment-free scope). Dim 2 corpus-exemplar quotes (per `voice_grounding.md`) will NOT match the essay body — the verifier tolerates non-matching quotes so long as ≥1 quoted span in the same justification matches the body (classification rule 1, the calibration-suffix tolerance), so every dim 2 justification quotes the offending essay passage IN ADDITION to the exemplar.
   - **Findings are a write-time self-check failure — correct before the sidecar lands** (the memo-review step 7c posture): a `missing_evidence` finding means the reviewer adds the verbatim quote + anchor (or, at full weight, the by-absence marker) to that dimension's justification and re-runs the check. A `fabricated_evidence` finding is the hard case — the quoted span does not appear in the body, so the reviewer MUST re-derive that dimension's justification from the actual body text (re-read the section, re-quote verbatim, and reconsider whether the score itself was grounded) — exactly the lazy-critic failure mode the gate exists for. The check is deterministic and cheaply re-runnable; correction converges in one or two passes. The staged sidecar MUST NOT exit the context block while `fabricated_evidence` findings persist.
   - **Advisory boundary**: this self-check governs the reviewer's OWN staging-dir output only. It does NOT gate the verdict (no new critical-flag category, no change to the `advance` aggregation), does NOT write a sidecar, and is NEVER run retroactively against existing review dirs by this command — legacy review siblings are immutable and the rule applies to NEW reviews only.
6c. **Annotate downstream-risk findings (issue #1197)**: for every `comments.md` entry written by 5b–5e, the dim 9 echo, the provenance back-check, or any other source, ask — *if the reviser applies `suggested_fix` literally, does that foreseeably break something else?* When yes, append a `Downstream risk:` line directly under that entry's `Comment:` line naming the predicted consequence, e.g.:

    ```
    ### §3 (line 88) — scope: reduce, major
    Excerpt: "as noted in the introduction, the 40% figure..."
    Comment: The introduction never states a 40% figure — this is either a stale cross-reference or the number itself drifted; re-derive and align both instances.
    Downstream risk: cross-reference-dangle — §1's opening paragraph is the referent; fixing only this instance without checking §1 leaves the two out of sync again.
    ```

    This is **additive per-finding annotation, not a new file or a required field** — most findings carry no `Downstream risk:` line at all (the common case), and its absence means "no foreseeable consequence identified," not "none exists." Annotate ONLY when a consequence is concretely foreseeable from the finding text itself — do NOT append a boilerplate disclaimer to every entry, and do NOT let this step slow down findings that plainly have no knock-on effect (a typo fix, a single-word swap). Two effect classes are common enough to name explicitly (the field stays free text — `anvil/lib/review_schema.py::Finding.downstream_risk` — so a third class never needs a schema change):
    - **`cross-reference-dangle`** — applying this fix would orphan a sentence, phrase, or figure reference elsewhere in the body that refers back to the text being changed. Name the referring location (heading/anchor or a short quoted phrase) so the reviser fixes both sides in one pass instead of re-discovering the dangle next cycle.
    - **`envelope-breach`** — the fix's likely size (a required addition — e.g. a missing citation link, a bridging clause for a numeric-consistency fix) would push the body past its declared word/line ceiling (the BRIEF `documents:` entry's `target_length`, or the default 500–1500 word envelope absent one). Name the ceiling and the expected direction/rough size of the overshoot.
    - Anything else foreseeable but not one of the above (e.g. fixing this instance leaves a parallel, unfixed instance of the identical defect elsewhere) still gets a `Downstream risk:` line — just without one of the two named tags; describe the consequence in prose.

    **This is essay-review's own prose contract, not a typed `_review.json` write** — essay's `scorecard_kind` stays `human-verdict` and this command does not construct `Finding` objects at runtime. The `Finding.downstream_risk` schema field documents the convention machine-readably for the framework (a future typed essay critic, or a `kind: tool_evidence` sibling, can populate it directly without a schema bump); this command's job is to make the SAME judgment call in the prose the human-verdict format already uses, so `essay-revise` (which reads `comments.md` directly, never the typed schema) can act on it in the very next pass.

Plus, **conditionally, flag 8**:

When a line attributed to Subject A carries characteristic markers that match Subject B's corpus and **contradict** Subject A's corpus, raise this flag. This is the **voice-identity failure only** (wrong voice in the wrong mouth) — the substance-level "the underlying event belongs to another speaker's testimony" is out of scope here (→ #597), do NOT adjudicate it. The justification MUST cite: (1) the attributed line, (2) the Subject A corpus showing why it does not fit, and (3) when identifiable, the Subject B corpus showing why it does fit better. This is an **additive** flag routed through the existing critical-flag machinery (same `Verdict.BLOCK` consequence via `critics.compute_verdict`) — it does NOT change the rubric total or the advance threshold (the `_meta.json` stamps stay `rubric_total: 44` / `advance_threshold: 35`). With fewer than 2 subjects declared the flag cannot fire (a single speaker has no alternate corpus to misattribute against).
   - **Fabrication-class flags (flags 9–13, conditional — issue #611)**: raised ONLY when the corpus tier is active (i.e., step 4c's `resolve_corpus_dirs` returned ≥1 non-missing dir) AND the back-check spot-sample caught clear fabrication evidence. Uses the `CriticalFlag.type` vocabulary from `anvil/lib/snippets/provenance.md` §Section 6: `fabricated_quote` (verbatim-quoted text absent from the corpus), `fabricated_fact` (a named date/name/event not traceable to any corpus passage), `misattribution_of_substance` (an event or memory attributed to a speaker whose corpus does not contain it — the **substance-level** flag, distinct from flag 8's voice-identity failure), `anachronism` (an era-incompatible detail contradicted by the corpus chronology), `unattributed_paraphrase` (authorial invention presented as a subject's memory without any corpus grounding). Each flag's justification MUST quote the offending artifact text and the corpus evidence (or its explicit absence). These are **additive**: routed through the existing `Verdict.BLOCK` machinery (`critics.compute_verdict` — no change needed) and do NOT change the rubric total or advance threshold (the `_meta.json` stamps stay `rubric_total: 44` / `advance_threshold: 35`). With the corpus tier inactive, flags 9–13 cannot fire.

   If none: "Critical flags: none."

Top 3 revision priorities: any gate failure first, then the highest-leverage dim deductions; when dim 9 scored below 4/5, at least one priority MUST be a `scope: reduce` item. List "What's working" — the moves the reviser must NOT sand off (voice signatures especially).

Absent entirely when nothing was excluded — same no-clutter posture as `missing`. This is what makes the calibration base auditable: a reader of `_summary.md` can see exactly which path(s) were dropped and why, without re-deriving the exclusion by hand (the defect this issue exists to close — four consecutive reviews recorded the same caveat manually with no framework signal behind it).

## What essay-review does NOT do

- **Never edits the body.** Read-only against `<thread>.{N}/`.
- **Never escalates rhetoric-lint severities** (the #463 advisory contract is fixed) and never blocks on lint output alone.
- **Never blocks on missing links to named entities** (coverage is dim 7 `major` territory; only *broken* links block).
- **Never crashes on a missing voice contract** — the `major` finding is the surface (the `customer_context.py` posture).
- **Don't be vague** ("voice feels off" without a corpus quote is a defective finding — and for a subject line, "doesn't sound like her" without a *transcript* quote is equally defective, #598), **don't moralize**, **don't recommend balanced point-counterpoint structure**, **don't suggest cutting items on the "What's working" list**, **don't defend voice moves you would make yourself** (for subject dialogue: don't defend a line you, the AI, would also write for that speaker — that convergence is the drift signal).
  - **"Don't suggest cutting items on the 'What's working' list" is a craft-preservation rule, not a relevance exemption** (issue #1148). It stops rubric-point-chasing from sanding a voice signature down while polishing it — it says nothing about whether the section that signature lives in belongs in *this* essay's argument. The 5e thesis-unity check is a different axis (does the section serve the thesis, not is it well-written) and MUST run — and MAY raise a `major` finding — on a section already listed as "What's working." A section can legitimately be both: a protected voice signature AND a thesis-unity finding recommending its removal (the operator decides; the finding is `major`, never critical, so the tangent can be kept knowingly). Read "don't suggest cutting" as scoped to craft-quality dimensions (2, 6, 8, 9), not to 5e/dim 7's relevance judgment.
- **Never adjudicate subject-line substance via the voice tier** — whether the underlying event/date/memory actually appears in the transcript corpus is the **corpus-provenance tier's** job (step 4c + flags 9–13, #611/#597), NOT the voice tier's. The Misattribution flag (8) is a *voice-identity* failure only; **substance-level** misattribution is `misattribution_of_substance` (flag 12) from the provenance tier. When the corpus tier is inactive, substance verification does not run at all — an ungrounded essay is scored on craft alone (byte-identical to pre-#611).
- **Never stamps `Verified against`/`Verified at` into `<thread>.{N}/provenance.md`** (issue #1198) — that file is part of the immutable version dir, not this command's sidecar. Step 4d records which priority rows checked clean in `_summary.md.claim_ledger.checked_clean_lines`; `essay-revise` is the one that mechanically stamps them, into the NEXT version's ledger, exactly as `essay-revise` (not `essay-review`) already owns the #868 mechanical anchor-repoint.

## Scorecard kind

This critic emits the `human-verdict` scorecard kind per `anvil/lib/snippets/scorecard_kind.md`. `_meta.json` MUST include `"scorecard_kind": "human-verdict"` plus the three rubric-stamping fields (`"rubric_id": "anvil-essay-v1"`, `"rubric_total": 44`, `"advance_threshold": 35`).

## Idempotence and resumability

Standard: a completed review is never re-run (sibling-exists check at step 1); a crashed review is re-runnable (the entry sweep removes this critic's stale staging dir; the gate CLIs sweep their own). Validation by file existence.

## Git sync (opt-in, off by default)

Per `anvil/lib/snippets/git_sync.md` (`.anvil/anvil/lib/snippets/git_sync.md` in an installed consumer repo): if `.anvil/config.json` exists and `git.commit_per_phase` is `true`, end this phase: stage only the dirs this phase wrote, commit as `anvil(<skill>/<phase>): <thread>.{N} [<state>]`, push if `git.push` is `true`. Git failures warn and continue — never fail the phase. When the config or knob is absent, skip this step entirely (default off).

This phase's specifics:

- **Ordering**: after the staged-sidecar atomic rename (issue #350) lands the final-named `<thread>.{N}.review/` — so only complete sidecars are ever committed.
- **Staging target**: ONLY this command's own outputs — `<thread>.{N}.review/` plus the `<thread>.{N}.numeric/` and `<thread>.{N}.hyperlinks/` gate sidecars its step-3 CLIs wrote (never other critics' dirs — the narrow scope keeps the hook safe under parallel fan-out).
- **Commit**: `anvil(essay/review): <thread>.{N} [REVIEWED]`.
